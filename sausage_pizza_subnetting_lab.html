🚨 Drawbacks of NOT Subnetting (One Giant Flat Network)

What happens when you leave an entire network as a single uncut pizza (p. 274)

1 Giant Broadcast Domain
  • 1. Packet Traffic Grinds to a Standstill (p. 274): Every broadcast "shout" (ARP requests, DHCP discovery) is heard by every machine in the broadcast domain, consuming bandwidth and CPU interrupts.
  • 2. Difficult Problem Isolation: Identifying and isolating network problems inside one gigantic flat network is far harder than in smaller connected subnets.
  • 3. Wasted IPv4 Addresses (p. 286): Putting a default Class C /24 (255.255.255.0 = 254 hosts) on a point-to-point WAN link that only has 2 routers wastes 252 host addresses per link!
  • 4. Inefficient WAN Spanning: Spanning one single large network across slow, expensive long-distance WAN links floods remote offices with local broadcasts.

✅ Benefits of Subnetting (Lammle p. 274, Fig. 8.2 p. 283 & p. 286)

How slicing the network into smaller broadcast domains optimizes traffic

Router-Isolated Subnets
  • 1. Reduced Network Traffic (~80% Broadcast Reduction): Routers create broadcast domains. Most traffic stays on the local subnet; only packets destined for other networks pass through the router.
  • 2. Optimized Network Performance (+50% Bandwidth, ~70% CPU Relief): Smaller broadcast domains mean less network traffic on each segment and faster throughput.
  • 3. Simplified Management: Problems are isolated to a single small subnet instead of taking down the whole organization.
  • 4. Real World WAN Efficiency (pp. 286–288 — The /30 255.255.255.252 Mask): Regardless of whether you have a Class A, Class B, or Class C address, the /30 mask always provides exactly 2 usable hosts — suited almost exclusively for point-to-point WAN links!
